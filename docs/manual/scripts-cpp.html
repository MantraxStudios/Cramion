Scripts en C++ y CVars

Cómo se escriben, el Inspector, el editor con IntelliSense, el aislamiento y las CVars.

En esta página

Además de Lua, los scripts se pueden escribir en C++, con toda la API de Lua disponible. Corren aislados en otro proceso (CramionScriptHost.exe): si un script falla (puntero nulo, excepción, recursión infinita, memoria agotada, abort() o un bucle sin fin), el motor no se cae. La Consola muestra el error con el archivo y la línea, ese script se desactiva hasta el siguiente Play y el proceso arranca de nuevo para los demás.

No hay que instalar nada: el editor trae su propio compilador (clang++ de llvm-mingw, en toolchain/) y clangd para el IntelliSense. Si falta, se usa el LLVM o el Visual Studio del sistema, o la ruta de la CVar script.cpp.Compiler.

Un script

  1. Proyecto > Crear > Script C++ (o Nuevo script C++ en el componente). Se pide el nombre (el de la clase) y se crean dos archivos, como en cualquier proyecto de C++: Clase.h (la clase y sus propiedades) y Clase.cpp (el código de sus métodos y CRAMION_SCRIPT). Se abre en el editor de código.
  2. Arrastra el .cpp o el .h a un objeto (en la escena, la Jerarquía, el campo Script del componente o el botón Add Component del Inspector). Se pone el componente C++ Script con su clase: no se escribe nada. Si el archivo tiene varias clases, se elige en una lista.
  3. Guarda (Ctrl+S): se compila solo. Las Property<T> salen en el Inspector con su control, como los campos públicos de Unity. En Play, al guardar se recarga al momento.
#include <cramion/Script.h>
using namespace cramion;

static CVar<float> g_salto("juego.Salto", 6.0f, "Altura de salto", CVarSaved);

class Jugador : public Script {
public:
    Property<float> velocidad{this, "velocidad", 5.0f, Range(0, 20), Tooltip("Metros por segundo")};
    Property<Prefab> bala{this, "bala"};                           // arrastrar un prefab
    Property<Entity> objetivo{this, "objetivo"};                    // arrastrar un objeto de la escena
    Property<Entity> luz{this, "luz", {}, Requires("Light")};       // solo objetos con Light
    Property<AudioClip> disparo{this, "disparo", {}, Header("Sonido")};
    Property<int> modo{this, "modo", 0, Options{"Andar", "Correr", "Volar"}};
    Property<std::vector<Entity>> puntos{this, "puntos"};          // una lista

    void update(float dt) override {
        Vec3 mover{Input::axis("Horizontal"), 0.0f, -Input::axis("Vertical")};
        entity().setMoveInput(mover * velocidad.get());              // Character Controller
        if (Input::keyDown("Space")) entity().jump(g_salto);
        if (Input::mouseButton(0, 1)) {
            Scene::instantiate(bala, entity().position());           // la API de Lua, en C++
            Audio::playOneShot(disparo);
        }
    }
    void onCollisionEnter(const Collision& c) override { Debug::log("choque con " + c.other.name()); }
};
CRAMION_SCRIPT(Jugador)

Lo mismo separado en .h y .cpp (así lo crea la plantilla):

// Jugador.h
#pragma once
#include <cramion/Script.h>
using namespace cramion;

class Jugador : public Script {
public:
    Property<float> velocidad{this, "velocidad", 5.0f, Range(0, 20)};
    void update(float dt) override;
};

// Jugador.cpp
#include "Jugador.h"

void Jugador::update(float dt) {
    entity().translate(Vec3{0.0f, 0.0f, velocidad * dt});
}

CRAMION_SCRIPT(Jugador)

Editor de código e IntelliSense

Los .cpp y .h se abren en el editor de código del motor con resaltado de C++ e IntelliSense de clangd (el mismo análisis que el compilador):

  • Sugerencias al escribir, tras ., -> y ::, o con Ctrl+Espacio (Tab/Enter para aceptar).
  • Errores y avisos en vivo, subrayados en rojo/amarillo, sin compilar; el mensaje sale al pasar el ratón.
  • Información del símbolo bajo el ratón (tipo, parámetros, documentación).
  • Firma de la función al abrir ( o escribir ,, con el parámetro actual resaltado.
  • Ir a la definición: F12 o Ctrl+clic (también en el SDK, cramion/Script.h).
  • Cierra solos ( [ { " ' y el < de plantillas e #include; Enter entre {} deja la llave de cierre en su línea.
  • Abrir cabecera (.h) / Abrir .cpp: el archivo de al lado con el mismo nombre (Alt+O).
  • Formatear (Mayús+Alt+F) con clang-format (incluido), sin mover el cursor de su sitio en el código.
  • Compilar (F7) y la Consola C++ debajo: los errores de compilación (doble clic va a la línea), los Debug::log de los scripts, sus fallos en Play y una línea de comandos para CVars o Lua.

Formato (Configuración del motor)

En Editar > Configuración del motor > Editor de código C++ (o el botón Configuración del editor de C++):

  • Formatear al guardar: activado, cada Ctrl+S deja el archivo con el estilo; desactivado, solo se formatea con el botón.
  • Estilo: Cramion (el del motor), LLVM, Google, Microsoft, Mozilla, WebKit, Chromium o Archivo (el .clang-format de la carpeta del proyecto, el mismo que usan VS Code o CLion).
  • Sangría y largo de línea, y un botón para guardar el estilo elegido como .clang-format del proyecto.
  • También: reiniciar clangd, el compilador en uso, compilar optimizado y ejecutar los scripts de C++ en Play.

Se guardan con el proyecto como CVars: editor.cpp.FormatOnSave, editor.cpp.FormatStyle, editor.cpp.IndentWidth y editor.cpp.ColumnLimit.

El editor escribe compile_commands.json en la carpeta del proyecto, así que VS Code, CLion o cualquier editor con clangd también entienden los scripts.

API

Scriptawake, start, update(dt), fixedUpdate(dt), lateUpdate(dt), onDestroy, onCollisionEnter/Stay/Exit(Collision), onTriggerEnter/Stay/Exit(Entity); entity().
Entityname, position/setPosition, rotation (grados), scale, forward/right/up, translate, rotate, lookAt, active/setActive, parent, destroy; componentes: has, add, component (JSON), setComponent, field/setField/getFloat/setFloat ("Light", "intensity"); física: velocity, addForce; Character Controller: move, isGrounded, setMoveInput, jump, setCrouch; y todos los métodos de la entidad de Lua (animación, audio, navegación, IK...).
Toda la API de LuaAudio, Scene, Input, Graphics, Navigation, Network, Http, Prefs, Random, Screen, Environment, Weather, Voxel, Fire, Fluid, DataPack, XR... con los mismos nombres y argumentos (generada desde el motor en cramion/Api.gen.h): cada función lleva el nombre de sus parámetros y su descripción, que el IntelliSense enseña al escribir y al pasar el ratón. Los parámetros que no se pasan son opcionales. Los argumentos y el resultado son Value: números, texto, Vec3, entidades, listas, objetos y funciones (callbacks).
Mathf, Vec2, Vec3, Quat, ColorMatemáticas como las de Unity, calculadas en el script (sin llamar al motor): Mathf::lerp/clamp/smoothDamp/moveTowards/deltaAngle/perlinNoise/fractalNoise..., Vec3::lerp/slerp/smoothDamp/angle/project/reflect/moveTowards, Vec3::up()/forward()..., Quat::euler/angleAxis/lookRotation/fromToRotation/slerp/rotateTowards, q.toEuler(), q * v, Color::hsv/lerp.
Mesh, StateMachineMallas por código (Mesh::cube(2.0f), m.setVertex(...), m.apply()) y máquinas de estados (StateMachine sm = entity().getStateMachine(); sm.go("Correr")).
Lua::call/get/set/sendLlamar a cualquier función de Lua por su nombre (también las de tus scripts de Lua).
Physics::raycast, Time, Debug::log/warning/error, Vec2/Vec3/ColorLlamadas propias rápidas (las que no devuelven nada van en lote).
CVar<T>, CVars::get/setVariables propias del juego (bool, int, float, double, std::string) y acceso a las del motor.

Aislamiento y límites

CVarQué hace
script.cpp.TimeoutMsTiempo máximo de una llamada (2000 ms). Si se pasa (bucle infinito), se corta.
script.cpp.MemoryLimitMBMemoria máxima del proceso de los scripts (1024 MB, con un Job Object de Windows). Al pasarse, las reservas fallan (std::bad_alloc).
script.cpp.MaxRestartsVeces que se rearranca el proceso en una sesión antes de rendirse.
script.cpp.Optimize, script.cpp.Compiler, script.cpp.EnabledCompilar optimizado, qué compilador usar, y apagar los scripts de C++.

Cada llamada de un script al motor es un mensaje entre procesos (unos microsegundos): para trabajo pesado conviene calcular en el script y llamar al motor lo justo. Los scripts de C++ funcionan en Windows (en Android no se ejecutan).

Variables (CVars)

Las CVars son variables de configuración con nombre, como las de Unreal o id Tech: tipo, valor por defecto, límites, descripción y banderas (guardada en ProjectSettings/CVars.json, solo lectura, truco). Las declara el motor (memoria de los scripts, tiempos...), los scripts de C++ (CVar<T>) y Lua (CVar.register).

  • Ventana > Variables (CVars) y memoria: todas, con filtro, para editarlas o volver al valor por defecto, y la memoria del editor, del equipo, de la VRAM y del proceso de scripts.
  • Consola (la línea de comandos de Scripts): nombre muestra el valor, nombre valor lo cambia, reset nombre, cvars filtro lista.
  • Lua: CVar.get(nombre), CVar.set(nombre, valor), CVar.register(nombre, defecto, descripcion, guardada), CVar.list(filtro), CVar.exists(nombre).
  • MCP: cvar_list, cvar_set y cpp_compile (compila y devuelve errores; también crea scripts).

Desde C++ en el motor:

static cvar::CVar<int> g_pool("mem.PoolMB", 256, "Tamano del pool", cvar::Saved, 16, 4096);
if (g_pool > 512) ...                 // lectura atomica, desde cualquier hilo
g_pool.onChanged([](cvar::CVarBase&) { /* reajustar */ });
