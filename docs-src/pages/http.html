Http manda y recibe datos de servidores y webs por HTTPS: tu propia API, un marcador de puntuaciones online, cuentas de jugador, noticias del juego o telemetría. Las peticiones van en segundo plano (el juego no se para) y la respuesta llega a una función que se llama en el hilo del juego, como un update más. Json convierte entre un Value y texto JSON. 

// Leer
Http::get("https://api.mijuego.com/noticias", [](const Values& a) {
    const Value& res = a[0];
    if (!res["ok"].asBool()) {
        Debug::log("No se pudo: " + res["error"].asString());
        return;
    }
    for (const Value& n : res["data"]["noticias"].items())   // res["data"] = JSON ya decodificado
        Debug::log(n["titulo"].asString());
});

// Enviar un objeto (va como JSON)
Http::post("https://api.mijuego.com/puntos", Value{{"jugador", "Ana"}, {"puntos", 1200}},
    [](const Values& a) {
        Debug::log(a[0]["status"].asString());   // 201
    },
    Value{{"Authorization", "Bearer " + token}});

Seguridad

  • Solo https://, con TLS 1.2 o 1.3. Windows comprueba el certificado del servidor: si está caducado, es de otro dominio o no es de una autoridad de confianza, la petición falla y no se envía nada.
  • http:// sin cifrar solo se permite a localhost / 127.0.0.1, para probar con un servidor en tu PC.
  • Las redirecciones nunca pasan de https a http.
  • Las cabeceras no pueden llevar saltos de línea (no se pueden colar otras cabeceras).
  • Cada petición tiene un tiempo máximo (20 s por defecto) y un tamaño máximo de respuesta (32 MB): un servidor que no contesta o que manda datos sin fin no bloquea ni llena la memoria.
  • Al salir de Play (o al cambiar de escena) lo que queda pendiente se cancela.

No pongas claves secretas en los scripts (la de tu base de datos, la de administrador de una API): los scripts van dentro del juego exportado y cualquiera puede sacarlas. El juego debe hablar con tu servidor, que es quien guarda las claves y comprueba lo que llega (que nadie mande 99999 puntos). Para identificar a un jugador usa un token que le dé tu servidor al iniciar sesión.

Funciones

FunciónQué hace
Http::get(url, funcion, cabeceras)Petición GET. funcion es una lambda [](const Values& a) {} que recibe la respuesta en a[0]. cabeceras (opcional) es un objeto Value{{"Nombre", "valor"}}. Devuelve el id de la petición, o un valor vacío (isNil()) si la dirección no vale (por ejemplo http:// a Internet).
Http::post(url, datos, funcion, cabeceras)Petición POST. datos: un texto (se manda tal cual, text/plain) o un objeto o lista (se manda como JSON, application/json). Una Content-Type propia en las cabeceras manda sobre esas.
Http::request(opciones, funcion)Cualquier método. opciones es un objeto con url, method ("PUT", "PATCH", "DELETE"...), headers, body, timeout (segundos, 20) y maxSize (bytes): Value{{"url", url}, {"method", "DELETE"}}.
Http::pending()Peticiones sin terminar.
Http::cancelAll()Cancela todas (sus funciones ya no se llaman).
Http::urlEncode(texto)Texto seguro para meterlo en una URL: "hola mundo" → "hola%20mundo".
Http::query(objeto)Parámetros de consulta: Http::query(Value{{"q", "ana"}, {"page", 2}}) → "page=2&q=ana".
Json::encode(valor, bonito)Value → texto JSON. Una lista sale como lista y un objeto como objeto. Vec3 sale como {x, y, z}. bonito = true lo sangra. Si hay algo que no se puede pasar (funciones), devuelve un valor vacío y avisa en la Consola.
Json::decode(texto)Texto JSON → Value (las listas desde 0, con [i] o .items(); null pasa a vacío). Si no es JSON, un valor vacío y un aviso en la Consola.

La respuesta

Campo (de res = a[0])Qué es
res["ok"]true (.asBool()) si llegó respuesta con estado 2xx.
res["status"]Estado HTTP (200, 201, 404, 500...). 0 si no hubo respuesta (sin Internet, certificado malo, tiempo agotado).
res["body"]El cuerpo como texto.
res["data"]Si la respuesta es JSON, ya decodificada (objetos y listas).
res["headers"]Cabeceras de la respuesta, con el nombre en minúsculas: res["headers"]["content-type"].
res["error"]Por qué falló (texto), si no es ok.
res["time"]Segundos que tardó.

Ejemplo: marcador online

#include <cramion/Script.h>
using namespace cramion;

class Marcador : public Script {
public:
    Property<std::string> servidor{this, "servidor", "https://api.mijuego.com"};

    void start() override {
        texto_ = Scene::find("UI_Marcador");
        cargar();
    }

    void cargar() {
        const std::string url = servidor.get() + "/puntos?" + Http::query(Value{{"nivel", 1}, {"limite", 10}}).asString();
        Http::get(url, [this](const Values& a) {
            const Value& res = a[0];
            if (!res["ok"].asBool()) {
                texto_.setText("Sin conexión (" + res["error"].asString() + ")");
                return;
            }
            std::string lineas;
            int i = 1;
            for (const Value& fila : res["data"].items())
                lineas += std::to_string(i++) + ". " + fila["nombre"].asString() + "  " + fila["puntos"].asString() + "\n";
            texto_.setText(lineas);
        });
    }

    void enviar(const std::string& nombre, int puntos) {
        Http::post(servidor.get() + "/puntos", Value{{"nombre", nombre}, {"puntos", puntos}},
            [this](const Values& a) {
                if (a[0]["ok"].asBool()) cargar();
            },
            Value{{"Authorization", "Bearer " + Prefs::getString("token", "").asString()}});
    }

private:
    Entity texto_;
};

CRAMION_SCRIPT(Marcador)

Probar con un servidor en tu PC

Mientras lo desarrollas, cualquier servidor local sirve con http://localhost:puerto (por ejemplo python -m http.server 8000 para leer archivos, o tu API con Node, Python o PHP). Para publicar el juego, pon el servidor con HTTPS (Let's Encrypt lo da gratis) y cambia la dirección.
