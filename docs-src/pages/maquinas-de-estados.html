Como los State Graphs de Bolt (Visual Scripting de Unity): la IA de un objeto se dibuja como un grafo de estados (Patrullar, Perseguir, Atacar...) unidos por transiciones con condiciones. Lo que hace el objeto en cada estado lo programa un script de C++ del objeto, que recibe un mensaje al entrar, al salir y cada frame. Las variables de la IA viven en una pizarra (blackboard) con tipo, que leen las condiciones y los scripts, y cada objeto puede tener sus propios valores.

Para verlo funcionando, crea un proyecto con la plantilla IA con máquinas de estados: dos enemigos patrullan, te persiguen, te atacan, huyen cuando les quitas vida (tecla F) y vuelven a casa.

Crear una máquina

En el Proyecto: clic derecho > Crear > Máquina de estados (IA) > Vacía o Enemigo de ejemplo. Se crea un archivo .crfsm y se abre la ventana Máquina de estados (también en Ventana > Máquina de estados, o con doble clic en el archivo). Para usarla, añade a un objeto el componente StateMachine y asígnale el .crfsm (o arrastra el .crfsm sobre el objeto en la Jerarquía, o usa Asignar a la selección).

La ventana

La máquina se abre en su propia pestaña (morada, Máquina: nombre) en la barra de espacios de trabajo, como los scripts: ocupa toda la ventana del editor. Doble clic en un .crfsm, Abrir en la ventana Máquina de estados en el Inspector o Ventana > Máquina de estados la abren; abrir otra reemplaza la de la pestaña. La escena sigue cargada: se vuelve a ella con la pestaña Escena y, en Play, la máquina se sigue viendo en vivo. La × de la pestaña la cierra (guardando los cambios).

IzquierdaLas variables (pizarra): nombre, tipo y valor inicial. En Play, los valores en vivo del objeto seleccionado (se pueden cambiar para probar), los triggers a mano y el historial de cambios de estado.
CentroEl grafo. Clic derecho en el fondo: crear un estado (vacío o de IA, con su nombre y color: Esperar, Patrullar, Perseguir, Atacar, Huir). Arrastrar desde el punto de la derecha de un estado hasta otro: crear una transición (o clic derecho > Crear transición). Arrastrar: mover. Rueda: zoom. Botón central o Alt+arrastrar: desplazar. Supr: borrar.
DerechaEl estado seleccionado (nombre, color, hacerlo de entrada, las transiciones que salen de él y la casilla Enviar OnStateUpdate) o las condiciones de la transición seleccionada.

Se guarda sola al terminar cada cambio. En Play, guardar recarga la máquina en caliente: cada objeto sigue en su estado y con sus variables. El estado activo del objeto seleccionado se ilumina, la barra azul cuenta el tiempo en el estado y la última transición tomada parpadea en naranja. En la transición seleccionada, un punto verde o rojo dice si cada condición se cumple ahora.

Nodos especiales

EntradaApunta al estado en el que empieza la máquina (clic derecho en un estado > Estado de entrada).
Cualquier estadoLas transiciones que salen de él se pueden tomar desde cualquier estado (morir, huir...). Los "sensores" que miran sus condiciones (la distancia al jugador, si lo ve...) los calcula el script de C++ del objeto y los guarda en la pizarra con sm.set.

La lógica de los estados

Los estados no llevan código: lo que pasa llega a los scripts de C++ del objeto como mensajes (onMessage, o on("OnStateEnter", ...) en start). Cada mensaje trae un objeto con machine (el nombre del .crfsm) y state:

"OnStateEnter"Al entrar en el estado. from: el estado de antes (nil al entrar en el de entrada).
"OnStateExit"Al salir. to: el estado al que va.
"OnStateUpdate"Cada frame mientras está en el estado, solo si el estado tiene marcada Enviar OnStateUpdate. dt y time (segundos en el estado).
 
void start() override {
    on("OnStateEnter", [this](const Value& v) {
        if (v["state"].asString() == "Perseguir") entity().moveTo(Scene::find("Jugador").position());
    });
    on("OnStateExit", [this](const Value&) { entity().stopMoving(); });
}

Lo que el script guarda en sus variables sigue ahí al cambiar de estado. Si un .crfsm antiguo tiene código Lua en un estado (o en Cualquier estado), el panel lo enseña de solo lectura con un aviso y el botón para quitarlo: ya no se ejecuta.

Transiciones y condiciones

Una transición se toma cuando se cumplen todas sus condiciones (sin condiciones, enseguida). Se miran una vez por frame, después de los update de los scripts. Si varias se cumplen, gana la de mayor prioridad; a igual prioridad, las de Cualquier estado y después el orden de la lista.

VariableCompara una variable con un valor (distancia < 10) o con otra variable escribiendo $nombre (distancia < $rangoVision). Bool, string y entity: igual, distinto, verdadero, falso. Los vec3 comparan su longitud.
TriggerSe cumple el frame siguiente a sm.trigger("nombre") (los triggers se consumen al mirarlos).
TemporizadorDespués de N segundos en el estado.
ExpresiónUna expresión con las variables por su nombre: números, textos, + - * / %, == != < <= > >=, and / or / not (o && || !) y paréntesis (vida < 30 and not alerta). Las llamadas a funciones no se pueden escribir.

Variables (pizarra)

Tipos: bool, int, float, string, entity (un objeto: se escribe su nombre, tag o UUID, o se arrastra desde la Jerarquía; desde un script, sm.get("objetivo").asEntity()) y vec3. En el Inspector del componente StateMachine, la casilla de cada variable le da a ese objeto su propio valor inicial (un enemigo que ve más lejos que otro). En Play el Inspector muestra el estado actual, permite saltar a otro y cambiar las variables en vivo.

Las máquinas corren en Play y en los juegos exportados (Windows y Android). Se actualizan en orden fijo, así el resultado es el mismo cada vez.

API desde C++

Desde cualquier script: StateMachine sm = entity().getStateMachine(); (o StateMachine::of(otro)). Referencia completa en StateMachine.

entity().getStateMachine()La máquina del objeto (comprueba con if (sm)). También StateMachine::of(entidad).
sm.state(), sm.previous()Nombre del estado actual y del anterior.
sm.stateTime(), sm.time()Segundos en el estado actual y desde que empezó.
sm.changes(), sm.running()Cambios de estado hasta ahora; si está en marcha.
sm.go("Estado")Cambia de estado por código (se aplica enseguida, con OnStateExit y OnStateEnter). También sm.changeState.
sm.isIn("Estado")Si está en ese estado.
sm.trigger("nombre")Dispara un trigger para las transiciones. StateMachine::broadcast("nombre") lo dispara en todas las máquinas.
sm.get("var"), sm.set("var", valor), sm.has("var")Variables de la pizarra (también sm.vars(), una copia). set de una variable que no existe la crea.
sm.states()Lista con los nombres de los estados.
sm.start(), sm.stop(), sm.restart()Reanudar, pausar o empezar de nuevo desde la entrada con las variables iniciales.

Los valores llegan como Value: sm.get("vida").asNumber(), sm.state().asString()...

Ejemplo: enemigo completo

Es la máquina Enemigo de ejemplo (todos sus estados con Enviar OnStateUpdate) y un script de C++ en el enemigo que hace cada estado; la plantilla IA con máquinas de estados trae uno parecido (Enemigo.cpp). Necesita un NavAgent en el enemigo, una NavMesh y un objeto llamado Jugador. Variables: objetivo (entity = Jugador), distancia, rangoVision (10), rangoAtaque (2), rangoPerder (16), vida (100), danio, radioPatrulla y casa (vec3).

Assets/Scripts/Enemigo.cpp

#include <cramion/Script.h>

#include <algorithm>
#include <string>
#include <vector>

using namespace cramion;

class Enemigo : public Script {
public:
    void start() override {
        sm_ = entity().getStateMachine();
        casa_ = entity().position();
        sm_.set("casa", casa_);
        jugador_ = sm_.get("objetivo").asEntity();
        // Puntos de ruta: objetos con tag "Waypoint", en orden de nombre.
        for (const Value& w : Scene::findAllWithTag("Waypoint").items()) ruta_.push_back(w.asEntity());
        std::sort(ruta_.begin(), ruta_.end(), [](const Entity& a, const Entity& b) { return a.name() < b.name(); });

        on("OnStateEnter", [this](const Value& v) { entrar(v["state"].asString()); });
        on("OnStateUpdate", [this](const Value& v) { cadaFrame(v["state"].asString(), v["dt"].asFloat()); });
        on("OnStateExit", [this](const Value& v) {
            const std::string estado = v["state"].asString();
            if (estado == "Patrullar" || estado == "Perseguir") entity().stopMoving();
        });
    }

    // Los sensores: la distancia al jugador, cada frame, para las transiciones.
    void update(float) override {
        if (!sm_ || !jugador_) return;
        sm_.set("distancia", Vec3::distance(entity().position(), jugador_.position()));
    }

private:
    void entrar(const std::string& estado) {
        if (estado == "Patrullar") { espera_ = 0.0f; siguientePunto(); }
        else if (estado == "Perseguir") recalcular_ = 0.0f;
        else if (estado == "Atacar") golpe_ = 0.0f;
        else if (estado == "Huir") alejarse();
        else if (estado == "Volver") entity().moveTo(casa_);
    }

    void cadaFrame(const std::string& estado, float dt) {
        if (estado == "Patrullar") {
            // Al llegar a un punto, espera un poco y va al siguiente.
            if (!entity().isMoving().truthy() && (espera_ += dt) > 1.5f) {
                espera_ = 0.0f;
                siguientePunto();
            }
        } else if (estado == "Perseguir") {
            recalcular_ -= dt;
            if (recalcular_ <= 0.0f) {
                entity().moveTo(jugador_.position());
                recalcular_ = 0.25f;
            }
        } else if (estado == "Atacar") {
            const Vec3 p = jugador_.position();
            entity().lookAt(Vec3{p.x, entity().position().y, p.z});
            golpe_ -= dt;
            if (golpe_ <= 0.0f) {
                golpe_ = 1.0f;
                Debug::log(entity().name() + " ataca (" + std::to_string(sm_.get("danio").asInt()) + " de danio)");
                if (StateMachine otra = jugador_.getStateMachine()) otra.trigger("golpeado");
            }
        } else if (estado == "Huir") {
            // Se aleja y se cura poco a poco.
            sm_.set("vida", std::min(100.0, sm_.get("vida").asNumber() + 8.0 * dt));
            if (!entity().isMoving().truthy()) alejarse();
        } else if (estado == "Volver") {
            // A casa y, al llegar, a patrullar por código.
            if (sm_.stateTime().asFloat() > 0.5f &&
                (!entity().isMoving().truthy() || entity().remainingDistance().asFloat() < 0.6f)) {
                sm_.go("Patrullar");
            }
        }
    }

    // De un punto de ruta a otro; sin ruta, puntos al azar de la NavMesh alrededor de casa.
    void siguientePunto() {
        if (!ruta_.empty()) {
            punto_ = (punto_ + 1) % ruta_.size();
            entity().moveTo(ruta_[punto_].position());
        } else {
            const Value p = Navigation::randomPoint(casa_, sm_.get("radioPatrulla"));
            if (!p.isNil()) entity().moveTo(p.asVec3());
        }
    }

    void alejarse() {
        const Vec3 yo = entity().position();
        const Vec3 lejos = yo + (yo - jugador_.position()).normalized() * 12.0f;
        Value p = Navigation::projectPoint(lejos, 8.0f);
        if (p.isNil()) p = Navigation::randomPoint(yo, 12.0f);
        if (!p.isNil()) entity().moveTo(p.asVec3());
    }

    StateMachine sm_;
    Entity jugador_;
    Vec3 casa_;
    std::vector<Entity> ruta_;
    std::size_t punto_ = static_cast<std::size_t>(-1);  // el primero es el 0
    float espera_ = 0.0f, recalcular_ = 0.0f, golpe_ = 0.0f;
};

CRAMION_SCRIPT(Enemigo)

Transiciones:

Patrullar → Perseguirdistancia < $rangoVision (otra: trigger ruido)
Perseguir → Atacardistancia <= $rangoAtaque
Atacar → Perseguirdistancia > $rangoAtaque y 0.5 s en el estado
Perseguir → Volverdistancia > $rangoPerder
Cualquier estado → Huirvida < 30, prioridad 10
Huir → VolverExpresión vida >= 60
Volver → Perseguirdistancia < $rangoVision

Desde otro script (por ejemplo, el arma del jugador):

for (const Value& item : Scene::findAllWithTag("Enemigo").items()) {
    const Entity e = item.asEntity();
    StateMachine sm = e.getStateMachine();
    if (sm && entity().distanceTo(e).asFloat() < 3.0f) {
        sm.set("vida", sm.get("vida").asNumber() - 35);
    }
}
StateMachine::broadcast("ruido");  // todos los enemigos lo oyen

Formato .crfsm

JSON legible (lo pueden escribir una persona o una IA). En las transiciones, from y to son el nombre del estado (o "any" = Cualquier estado). 

{
  "uuid": "…",
  "entry": "Patrullar",
  "variables": [ { "name": "distancia", "type": "float", "value": 9999 } ],
  "states": [ { "name": "Patrullar", "position": [0, 0], "color": [0.2, 0.45, 0.25], "send_update": true } ],
  "transitions": [
    { "from": "Patrullar", "to": "Perseguir", "conditions": [ { "type": "variable", "variable": "distancia", "compare": "<", "value": "$rangoVision" } ] },
    { "from": "any", "to": "Huir", "priority": 10, "conditions": [ { "type": "expression", "expression": "vida < 30" } ] }
  ]
}
