Pruebas automáticas (como el Test Runner de Unity): pruebas de C++ con CRAMION_TEST y Assert que se ejecutan en el editor o desde la línea de comandos (integración continua). Corren en Play, una detrás de otra y frame a frame en la escena: pueden esperar frames, segundos o a que pase algo.

Escribir pruebas

Son archivos .cpp dentro de Assets/Tests (o cualquier .cpp de Assets que use CRAMION_TEST) que incluyen <cramion/Test.h>; se compilan con los demás scripts de C++. Ventana > Pruebas > Nueva prueba crea uno de ejemplo. 

#include <cramion/Test.h>
#include <cmath>
using namespace cramion;

CRAMION_TEST(LasMatematicasFuncionan) {
    Assert::equal(2 + 2, 4);
    Assert::approx(std::sqrt(2.0), 1.41421, 0.0001);
}

CRAMION_TEST_TIMEOUT(ElJugadorCaeAlSuelo, 10.0f) {
    Entity jugador = Scene::find("Jugador");
    Assert::notNull(jugador, "no hay jugador");
    co_await Test::waitSeconds(2.0f);
    Assert::less(jugador.position().y, 1.5f);
}

CRAMION_TEST(ElJugadorSalta) {
    Entity jugador = Scene::find("Jugador");
    const float antes = jugador.position().y;
    jugador.jump(2.0f);
    co_await Test::waitSeconds(0.3f);
    Assert::greater(jugador.position().y, antes, "no subio");
    co_await Test::waitUntil([=] { return jugador.isGrounded(); }, 5.0f, "no volvio al suelo");
}

Esperas (con co_await): Test::waitFrames(n), Test::waitSeconds(s), Test::waitUntil(condicion, limite, mensaje); una prueba que espera sale antes con co_return. Comprobaciones: Assert::isTrue/isFalse/equal/notEqual/near/approx/isNull/notNull/greater/less/atLeast/atMost/throws/fail. Una prueba falla en la primera comprobación que no se cumple (con su mensaje), con una excepción o al pasar su tiempo máximo (30 s, o el de CRAMION_TEST_TIMEOUT).

Test Runner

Ventana > Pruebas (Test Runner): Ejecutar todas, Parar y Nueva prueba. Entra en Play en la escena abierta, pone un objeto Pruebas con el script CramionTests (el que las ejecuta en orden), ejecuta y vuelve a Edición. Los resultados salen agrupados por archivo (✔ bien, ✖ mal, – saltada) con el mensaje, el tiempo y las comprobaciones.

Línea de comandos (CI)

CramionEditor.exe --run-tests "C:\Juegos\MiJuego" --junit resultados.xml

Abre el proyecto (con su escena inicial), ejecuta todas las pruebas, escribe cada resultado en la consola y, si se pide, un informe JUnit (lo entienden GitHub Actions, Jenkins, GitLab...) y cierra. Código de salida: 0 todas bien, 1 alguna falló, 2 no hay pruebas, 3 no se pudo abrir el proyecto.

El juego exportado (Windows) también las ejecuta, tal cual se publica (paquete .crpack, scripts ya compilados): las pruebas van dentro si están en los scripts de C++ del proyecto al exportar. Es una ventana, así que desde cmd se espera con start /wait: 

start /wait MiJuego.exe --run-tests --junit resultados.xml
echo %ERRORLEVEL%

Mismos códigos de salida (3: el juego no llegó a ejecutarlas, por ejemplo porque la escena inicial no cargó). En Android no hay línea de comandos.
