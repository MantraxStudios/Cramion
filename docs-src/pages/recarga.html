Si guardas un .cpp o un .h durante el modo Play, se compila y la DLL nueva se carga al momento: los scripts se recrean sin parar el juego y conservan sus Property<T> con los valores que tenían en ese momento (no se vuelve a llamar a awake() ni a start()). Un aviso abajo a la derecha dice si se recargó o, si no compila, el primer error (el juego sigue con la DLL anterior). Con Formatear al guardar activado (Configuración del motor), se formatea antes.

Los errores de compilación salen en la Consola C++ del editor de código (doble clic va a la línea) y subrayados en el código; los fallos en Play, con el archivo y la línea. Un script con errores no detiene al resto.

La línea de comandos de la Consola C++ cambia CVars (r.Shadows 0, cvars filtro) y ejecuta código suelto del juego, por ejemplo para mover un objeto mientras pruebas.

Conservar el resto del estado

Las variables privadas (las que no son Property<T>) se guardan con onBeforeReload() y se recuperan en onAfterReload() de la instancia nueva. Ahí también se vuelven a registrar los callbacks (Input::bindAction, Network::on...), porque eran del proceso anterior. 

Value Torreta::onBeforeReload() {
    return Value{{"municion", municion}, {"enfriamiento", enfriamiento}};
}

void Torreta::onAfterReload(const Value& estado) {
    municion = estado["municion"];
    enfriamiento = estado["enfriamiento"];
}

La CVar script.cpp.HotReloadKeepState (activa por defecto) lo controla: apagada, los scripts empiezan de nuevo como antes.
